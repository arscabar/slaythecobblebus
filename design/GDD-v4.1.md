> 상태: **기획 확정 초안 · 데이터 참조 정합성 확인 · 실제 Cobbleverse 애드온 미구현**  
> 기반: `CobbleSpire_integrated_master_v3.xlsx`, `CobbleSpire_integrated_v3_data.json`, 기존 협의 내용  
> 목적: 기존 50종 캐릭터/165종 모험 도구와 21개 악역 조직 편성을 유지하면서, 모험 도구 발동 이벤트·조건·효과·발동 횟수, 몬스터 기술/룰베이스 인텐트, 보스 페이즈를 미리 고정된 데이터 ID로 정의한다.

## 1. 게임 테마와 플레이 형식

- 지도: 마인크래프트 월드 안에 걷는 지도는 **사용하지 않는다**. 독립적인 Slay the Spire 스타일 3막 분기형 UI 지도를 사용한다. 노드에는 일반전, 엘리트, 상점, 휴식, 보물볼, [?] 이벤트, 보스가 배치된다.
- 핑: 멀티플레이에서는 지도 노드 ID를 공유 핑으로 전송한다. 기본 표시 15초, 특정 도구로 연장 가능. 핑은 경로 확정이 아니며 파티 경로 결정과 별개이다.
- 캐릭터: 플레이어마다 최대 **3마리**를 보유하고, 전투에는 한 번에 **1마리**가 출전한다. 기본 타입 불꽃/물/풀에서 시작하고 장기적으로 18타입, 50종 후보로 확장한다.
- 기술 덱: 카드 비주얼 없음. 포켓몬별 독립 덱을 사용한다. 출전 포켓몬의 기술 슬롯은 4개이고, 플레이어 기본 에너지는 3이다. 기술 사용 시 해당 슬롯만 즉시 보충한다. 손패 아닌 기술 슬롯; 사용 후 버림·리셔플·소멸·보존 규칙 유지.
- 전투: 적 포켓몬 1~3마리 동시 등장. 트레이너 사람 모델이나 NPC는 보여주지 않는다. 적의 공격/공격성 상태이상 기술은 **각 플레이어의 살아 있는 출전 포켓몬**을 대상으로 하며 명중·피해는 각 대상마다 판정한다.
- 조직 테마: 1막 **로켓단**, 2막 **마그마단/아쿠아단**, 3막 **갤럭시단**. 조직은 UI·보상·적 편성의 테마이다.
- 상성: **원본 타입 상성 결과가 완전 무효(×0)인 플레이어→적 직접 공격을 ×0.5로 완화**하는 A안이 데이터에 반영되어 있다. ×0.25·×4 등 다른 배율은 이 버전에서 그대로 둔다. 원본 특성 면역·상태이상 면역까지 자동 해제하지 않으며, 모든 적에게 스텔라 외형을 강제하지 않는다.
- 레벨/휴식: 런 Lv.1~10의 캐릭터별 성장량을 기존 v3에서 유지한다. 휴식처에서는 휴식 회복과 기술 인스턴스 하나 강화 중 선택한다. 회복을 선택한 플레이어의 파티에서 살아 있는 포켓몬 전원이 각각 자기 최대 HP의 30%를 기본으로 회복한다. 최대 HP까지만 회복하며, 기절한 포켓몬은 부활하지 않는다. 기존 유물의 회복 비율 변경과 선택 제한은 적용한다.
- 유물 UI: 일반 도구(일반), 희귀 도구(희귀), 특급 도구(고급), 전용 보물(고유). 원본 지닌물건은 별도 1칸이다.

## 3. 공통 이벤트 엔진

### 3.0 v4.1 전투·런 규칙

- **시작과 영입** — 대표 1마리를 선택하면 파트너 2마리를 자동 지급한다. 대표와 파트너를 합한 세 포켓몬 사이에 공통 타입이 없어야 하며, 복합 타입은 두 타입 모두 비교한다. 시작 파티는 출전 1마리와 대기 2마리다. 물음표 이벤트와 일부 보상 노드에서 영입하며, 상점과 특정 이벤트에서도 포켓몬을 교체할 수 있다. 파티가 가득 찼다면 기존 포켓몬과 교체한다. 새 포켓몬은 자신의 덱을 사용한다.
- **전투 중 교체** — 일반 교체는 플레이어 페이즈에 플레이어당 라운드 1회, 에너지 1을 사용한다. 일반 교체 횟수는 라운드 시작에 초기화한다. 수면·마비 중에도 일반 교체할 수 있다. 교체 후에는 남은 에너지로 기술을 사용할 수 있으며, 새 출전 포켓몬의 상태이상 등 기존 기술 사용 판정은 적용한다. 적 공격 중 출전 포켓몬이 기절하면 진행 중인 적 행동을 끝까지 정산한다. 같은 적 행동의 남은 효과는 대기 포켓몬에게 넘기지 않는다. 다음 플레이어 행동 전에 무료로 강제 교체하며, 일반 교체 횟수를 쓰지 않는다. 해류의 고리(S02)와 로토무 회전장치(B02)의 리롤 효과는 기술 슬롯에만 적용한다. B02의 기존 기본 에너지 +1은 유지한다.
- **교체 시 상태** — 교체되어 나가는 포켓몬의 임시 능력치 랭크를 초기화한다. HP·기절 여부·메가진화 폼·상태이상과 남은 시간·독립 덱과 강화는 보존한다. 종족값과 런 성장치는 유지한다. 메가 폼은 같은 전투에서 대기·재출전 중 유지되고 전투 종료 시 원래 폼으로 복귀한다.
- **대기 중 효과** — 독·화상은 대기 중 보존하되 대기 중에는 해당 지속 피해를 적용하지 않는다. 교체되어 나가는 대상에게 붙은 씨뿌리기와 구속은 해제한다. 전장 전체 효과는 유지한다. 전투 중 포켓몬 대상 유물·지닌물건 효과는 대기 포켓몬이 대상에 명시된 경우에만 대기 포켓몬에게 적용한다.
- **재출전 덱 상태** — 같은 전투에서 각 포켓몬의 기술 슬롯, 드로우 순서, 버린 덱, 소멸 더미를 개별 보존한다. 교체 후 다시 출전하면 자신의 상태 그대로 이어서 사용한다. 재출전으로 기술을 새로 뽑거나 드로우를 섞거나 소멸한 기술을 복구하지 않는다.
- **상태이상** — 수면·마비는 부여된 라운드를 건너뛰고, 이후 공동 `ROUND_END`에 출전 중인 포켓몬만 1회 차감한다. 대기 중 남은 시간은 유지한다. 라운드 도중 전투가 끝나면 별도 차감을 발생시키지 않는다. 승리·패배 시 출전·대기를 포함한 파티 전원의 상태이상과 임시 능력치 랭크를 초기화한다.
- **승패 판정** — 진행 중인 행동의 피해·반동·연계 효과와 기절을 모두 정산한다. 실제 적 페이즈 종료에 도달했다면 `ENEMY_PHASE_END`와 C04 등 해당 이벤트의 효과를 처리한 뒤 승패를 판정한다. 페이즈 도중 전투가 끝나거나 플레이어 페이즈에서 끝나면 적 페이즈 종료를 별도로 발생시키지 않는다. 출전·대기를 합쳐 살아 있는 아군이 없으면 마지막 적도 함께 기절했더라도 패배다. 아군이 하나 이상 살아 있고 마지막 적이 기절했으면 승리다. 양측에 생존 포켓몬이 있으면 전투를 계속한다.
- **승리 정산** — 승리 조건이 충족되면 HP와 생존 여부를 기록한 뒤 `BATTLE_WON`을 전투당 한 번 확정한다. 기존 훈련점수·레벨업을 적용한 후, 승리 직전 기절했던 포켓몬을 각각 최대 HP의 20%로 부활시킨다. 승리 기본 부활량은 소수점을 버리며 최소 1 HP다. 생존 포켓몬의 기본 승리 정산 HP는 그대로이며 기존 레벨업·명시적 회복 효과는 적용한다. 생장씨앗(S03)과 단합의 의료 키트(C01, 구 공동 구급함)의 생존 조건은 승리 직전 기록을 사용한다. 구조의 깃발(C04, 구 구조 휘장)은 협동 전투에서 소유자 생존, 기절 아군 존재, 막당 파티 1회 조건을 충족할 때 실제 적 페이즈 종료에 아군 1마리를 최대 HP 20%로 부활시킨다. C04로 살아난 포켓몬이 승리 직전에도 생존했다면 기본 부활 대상이 아니다. 최종 HP를 반영한 후 보상·지도로 진행한다. 패배 또는 런 종료에는 승리 부활이 적용되지 않는다.
- **런 운영** — 진행 중 상태는 서버 메모리에 유지한다. 종료하거나 서버를 재시작하면 런을 폐기한다. 다시 시작하면 이전 상태를 폐기하고 새 런을 만든다. 저장·불러오기는 제공하지 않는다.


### 3.1 처리 흐름

1. 클라이언트가 `slot_index`, `move_instance_id`, `request_id`가 포함된 사용 요청을 전송한다.
2. 서버가 플레이어 페이즈·비용·슬롯 일치 여부·상태를 확인하여 **중복 요청 방지**한다.
3. `BEFORE_MOVE_COST` → 비용 확정 및 차감 → `BEFORE_MOVE_ACCURACY` → 대상별 명중 판정 → `BEFORE_ATTACK_DAMAGE` / `BEFORE_STATUS_CHANCE` / `MOVE_HIT` 또는 `MOVE_MISS` 순서로 처리한다.
4. 원본 기술 효과를 적용하고 해당 조건에 맞는 모험 도구/타입 효과를 처리한다.
5. `MOVE_RESOLVED` → 버린 덱/소멸 덱 이동 → `SLOT_REPLACED` → 클라이언트 HUD 동기화.
6. 플레이어들이 공동 페이즈를 끝내면 적의 **확정 인텐트**를 순서대로 실행한다. 기절한 적의 인텐트는 취소한다.
7. 결과·전투 RNG 시드·실행한 발동 규칙 ID를 서버 로그에 기록하고 승패를 결정한다.

**주의:** 하나의 기술이 적 세 마리를 명중시키더라도 `MOVE_RESOLVED`는 1회다. `MOVE_HIT`은 대상별 이벤트이므로, '기술당 1회' 도구는 이벤트 고유 ID로 중복 발동하지 않도록 한다. 파티 방어 도구의 배율도 피해 대상마다 개별 적용한다.

### 3.2 공통 효과 객체

```json
{
  "rule_id": "G01-E01",
  "event": "ROUND_START",
  "priority": 100,
  "conditions": [{"op": "FIRST_ROUND"}],
  "actions": [{"op": "GRANT_ENERGY", "value": 1, "value_kind": "scalar"}],
  "activation_limit": {"scope": "BATTLE", "max_activations": 1},
  "dispatch_scope": "PER_SOURCE_EVENT",
  "resolution": "SERVER_AUTHORITATIVE",
  "definition_status": "DEFINED_UNTESTED"
}
```

유물마다 고유 코드 파일을 두지 말고 동일한 구조를 사용한다. **90개 연산자 이름이 각각 별도 클래스 90개를 강제한다는 뜻은 아니다.** 에너지·피해·드로우·보상·UI·상태이상·스코프 등 공통 핸들러 군으로 묶어 구현한다.

### 3.3 발동 횟수 범위

- `RUN`: 한 런 전체; `ACT`: 한 막; `BATTLE`: 한 전투; `ROUND`: 한 플레이어 라운드.
- `BATTLE_PHASE`: 특정 적 페이즈; `MOVE_INSTANCE`: 특정 기술 인스턴스; `REWARD`: 한 번의 보상 선택.
- `SHOP`, `REST`, `CHEST`, `EVENT`, `ENCOUNTER` 등은 각 해당 노드 또는 인스턴스 범위.
- `PASSIVE`: 선언된 조건이 유지되는 동안 해당 이벤트마다 평가. 반드시 적용 가능한 대상·반복 스택 여부를 검사.
- 큐에 예약된 효과는 `next_eligible_or_scope_end` 정책으로 사용하거나 만료한다.

최종 계산 순서는 **모드 비용 할인 → 명중/상성 → 원본 기술 효과 → 모드 전용 피해·상태 효과 → 기절/상태 정산**에 맞춰 세분화하되, 정확한 Cobblemon 효과 브리지 우선순위는 구현 중 원본 엔진과 대조해야 한다.

| 고급 | 특급 도구 | 20 | **한 런에 해당 등급 1종만 노출** | 동일 플레이어의 고유와 상호 배타 |
| 고유 | 전용 보물 | 10 | **한 런에 해당 등급 1종만 노출** | 동일 플레이어의 고급과 상호 배타 |

고급·고유 3택 1 상자에서는 고급/고유 중 **최대 한 후보**만 보여주고, 나머지는 일반·희귀 후보로 채운다. **노출한 시점에 해당 등급 카운터가 소모되는 기존 v3 정책**을 계승한다. 선택하지 않더라도 재등장하지 않는다. 멀티 런에서는 카운터를 모든 참가자가 공유한다. 보상 선택 UI에서 소유 불가능한 플레이어에게는 대체 보상을 제공한다. 

고유 유물 10종은 타입·종족 적합성 필터를 사용하며, 예를 들어 용염의 비늘은 리자몽, 심해의 포격핵은 거북왕에게 한정하는 초안이다. 다른 캐릭터의 고유 후보가 비어 있으면 해당 캐릭터에 무관한 도구를 무작위 지급하지 않는다.

**잔여 설계 검토 사항:** '고급 유물을 반납하고 고유 유물을 교체 획득'은 제안 단계이다. 기본 실행 규칙은 상호 배타이며 자동 교체하지 않는다.

## 5. 몬스터 AI — 간단한 룰베이스

한 몬스터에 3~5개 원본 기술 후보를 두고, 다음 순서로 인텐트를 선택한다.

1. 현재 보스 페이즈에 따라 적용 가능한 기술·행동 가중치를 불러온다.
2. `HP≤40%` 회복, 대상 미상태이상 시 방해, 자기 강화 랭크 부족 시 강화 등의 조건을 확인한다.
3. 쿨다운·전투당 최대 사용 횟수를 검사한다.
4. 우선순위가 높은 규칙을 선택하고, 동순위/기본 공격은 가중치 추첨한다.
5. 모든 조건 규칙이 실패해도 `ALWAYS` 기본 공격을 사용한다.
6. 이번 적 페이즈의 행동 후보를 정한 뒤 편성 조정기(`EncounterDirector`)가 강한 공격·강제 상태이상의 동시 사용 횟수를 제한한다.
7. 인텐트를 모든 참가자 UI에 공개한다. 명중과 예상 피해는 각 플레이어 능력치에 따라 따로 표시한다.

**예:** 아보크는 뱀눈초리(대상 상태 조건) → 똬리틀기(강화 랭크 조건) → 독찌르기/깨물어부수기(기본 가중치 공격) 순으로 고려한다. 단, 각 기술의 원본 타겟 지정·학습 가능성·효과는 미검증이므로 개발용 정책 테스트를 통과한 뒤 확정한다.

## 6. 보스 페이즈와 편성 구간

- **1막 로켓단:** 니드킹 단독 보스 또는 니드킹+니드퀸. 기본/폭주 2페이즈.
- **2막 마그마단:** 메가폭타 중심 보스, 2페이즈. **아쿠아단:** 메가샤크니아, 2페이즈.
- **3막 갤럭시단:** 포푸니라+돈크로우, 또는 크로뱃까지 총 3마리. 탐색전/본격전/최후의 저항 3페이즈.
- 체력 기준은 개별 보스가 아니라 **생존·기절한 적을 모두 포함한 편성 초기 HP 대비 잔여 HP 비율**이다. 같은 페이즈에서 임계치를 여러 번 지나도 한 번만 전환한다.
- 페이즈 전환 자체로 숨겨진 즉시 추가 공격을 실행하지 않는다. 인텐트는 다음 플레이어 페이즈 시작 전에 갱신한다.

## 7. 데이터 기반 밸런스 초안

기존 v3의 기준과 최근 논의에서 확정한 내용을 우선한다.

| 항목 | 값 |
|---|---|
| 기준 전투 레벨 | 50 |
| 런 레벨 | 1~10 |
| 기본 기술 슬롯 | 4개 |
| 기본 에너지 | 3 |
| 플레이어 수 | 1~4명 |
| 적 동시 등장 | 1~3마리 |
| 파티별 적 HP 배율 | 1.00 / 1.85 / 2.70 / 3.55 |
| 적 수별 **전체** HP 배율 | 1.00 / 1.10 / 1.15 |
| 일반/엘리트/보스 전체 HP 배율 | 1.00 / 1.55 / 2.40 |
| 파티 수별 적 1인당 피해 계수 | 모두 1.00 |
| 적 AI 행동 횟수 | 파티 수로 자동 증가시키지 않음 |
| 공격 타입 무효 완화 | 플레이어→적의 타입 무효 ×0 → ×0.5 |

전체 HP 예산은 **단계 기준값 × 등급 × 적 수 × 파티 배율을 한 번만 곱한 뒤 편성 내 포켓몬에게 분배**한다. 이 수치는 아직 실제 승률로 검증하지 않았다.

## 8. 정적 검증 결과 및 기술적 한계

`qa_validation.json`의 성공 조건:

- 165개 도구 ID가 유일하고 각 도구가 최소 1개의 발동 규칙을 갖는다.
- 모든 유물 규칙이 등록된 이벤트·조건·동작 ID만 참조한다.
- 각 적 포켓몬에 3~5개의 기술 후보가 있고, AI가 자기 기술 풀 밖의 ID를 참조하지 않는다.
- 각 AI는 `ALWAYS` 기본 공격 폴백을 갖는다.
- 21개 편성의 적 ID가 25개 포켓몬 프로필로 해석된다.
- 보스 6개 편성에 14개 단계가 연결된다.
- 기존 50종·165종 레코드가 유실되지 않는다.

**게임 내 구현·시뮬레이션 검증과는 다르다.** 특히 (1) 원본 종족/폼 식별자 (2) 기술 배움표·특성 (3) 다인 동시 전투에서 원본 Move 효과 지원 (4) 변신 특수 폼 (5) 유물 발동 순서 (6) 초·후반 난이도는 추후 확인이 필요하다.

## 9. 구현 시 가장 먼저 연결할 인터페이스

```text
GameRunState          ── 지도/UI/보상/레벨/유물 등장 카운터의 서버 메모리 상태
BattleSession        ── 서버 전투 상태 머신
PokemonBridge        ── 원본 포켓몬 스탯/특성/기술/폼 조회
MoveCompatibility    ── 원본 효과 지원/예외 변환/지원 제외
IntentRuleEngine     ── 몬스터 룰 평가, 대상별 피해 예상치
EncounterDirector    ── 적 1~3마리 인텐트 총량 조정
EffectDispatcher     ── 공통 발동 이벤트 → 조건 → 효과 처리
PartySync            ── 공동 플레이어 페이즈와 지도 핑
RewardRuleEngine     ── 모험 도구 보물볼·상점·기술 획득
BalanceValidator     ── HP 예산·에너지 반복·테스트 리포트
```

우선 **기본 적 3종 + 엘리트 1종 + 보스 1종 + 서로 다른 효과 계열의 도구 15종**으로 실제 실행기를 시험한 다음, 이미 사전 정의된 나머지 데이터를 활성화한다. 새 데이터를 다시 작성하는 것이 아니라 기존 정의의 구현 상태·밸런스 수치를 갱신하도록 한다.

| 검증 | 재현 절차와 통과 기준 |

| V1 · 로딩과 격리 | 대상 버전으로 빌드한 애드온을 테스트 클라이언트와 전용 서버에서 시작한다. 신규 런에 들어가기 전후로 일반 Cobblemon 전투와 월드 데이터를 비교한다. 의존성 오류, 애드온에 의한 기존 포켓몬·인벤토리 데이터 변경, 시작·종료 시 남은 런 상태가 없어야 한다. |
| V2 · 파티·교체·덱 | 복합 타입의 한 타입이라도 겹치는 시작 조합을 거부한다. A→B→A 교체 후 슬롯, 드로우 순서, 버린 덱, 소멸 더미가 동일해야 한다. 일반 교체는 에너지·횟수를 한 번씩 차감하며, 기절 시 현재 적 공격이 끝날 때까지 피해를 대기 포켓몬에게 넘기지 않고 다음 플레이어 행동 전에 무료 교체한다. |
| V3 · 상태·메가 폼 | 수면·마비는 부여 라운드와 대기 중에 차감되지 않고, 이후 출전한 상태에서 라운드당 한 번 차감된다. 수면·마비 중 교체 및 재출전 후 기술 판정을 확인한다. 대기 중 독·화상 피해 정지, 씨뿌리기·구속 해제, 전장 및 대기 대상 유물 효과, 메가 폼 유지와 전투 종료 복귀도 확인한다. |
| V4 · 승패·회복·유물 | 마지막 적과 아군 전원이 동시에 기절하면 패배하고, 살아 있는 대기 포켓몬이 있으면 승리해야 한다. C04는 조건을 충족한 실제 적 페이즈 종료에만 승패보다 먼저 처리한다. 이미 부활한 포켓몬에 승리 기본 부활이 중복 적용되지 않아야 한다. 최대 HP 19의 승리 기본 부활은 3 HP, 최대 HP 4는 1 HP다. 휴식처에서는 선택한 플레이어의 생존 포켓몬마다 최대 HP의 30%를 기본으로 회복하고, 최대 HP 상한과 기존 유물 예외를 적용한다. |
| V5 · 협동과 런 전체 | 전용 서버에서 1~4인으로 진행한다. 중복·동시 요청에 비용이나 보상이 두 번 적용되지 않고, 재접속한 참가자를 포함해 모든 클라이언트가 같은 서버 확정 상태를 표시해야 한다. 한 런에서 3막과 보상·휴식·상점을 검증하고, 종료·다시 시작·서버 재시작으로 이전 런이 폐기되는지 확인한다. |

실행 결과에는 모드팩·애드온 버전, 플레이어 수, 시드, 재현 명령 순서, 기대값·실제값, 관련 서버 이벤트 로그를 기록한다. 실패는 재현 가능한 사례로 남기고 수정 후 해당 사례와 선행 단계의 회귀 검사를 다시 실행한다. 배포 완료는 V0~V5를 통과하고 활성 콘텐츠의 미지원 항목을 정리한 뒤 판정한다.
