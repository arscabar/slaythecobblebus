# 안정적인 카드 조작과 이야기·이벤트 화면 설계

설계 제안이며 구현된 기능이 아니다. `GDD-v4.2.md`의 손패 규칙을 우선한다. 기존 이벤트 레지스트리의 `EVENT_ENTERED` 등은 규칙 처리용 이벤트 ID이며 곧바로 플레이어에게 보여줄 이야기와 삽화가 갖춰졌다는 뜻은 아니다. 이야기 콘텐츠와 협동 선택 방식은 별도 기획·구현이 필요하다.

## 카드 드래그: 안정성을 우선한 조작

```text
대기 → 카드 누름 → 일정 거리 이동 → 드래그 시작 → 대상 강조 → 놓기
                 └ 짧게 클릭 → 카드 선택 → 대상 클릭 또는 키보드 선택
드래그 중 Esc / 빈 곳에 놓기 / 화면 닫기 → 취소, 손패 복귀
대상 위에 놓기 → 서버 처리 대기 → 확정 연출 또는 실패 사유 표시
```

- 드래그 시작까지 최소 이동 거리를 두어 클릭과 구분한다. 손가락 떨림이나 작은 마우스 이동으로 카드가 실수로 사용되지 않게 한다.
- 카드의 실제 보이는 영역과 대상의 화면상 선택 영역을 구분한다. 적의 모델 외에 이름표도 선택 가능하며, 서로 겹칠 때는 이름표·대상 목록을 제공한다. 커서가 유효한 영역에 들어갔을 때만 해당 대상과 이름을 강조한다.
- 끌고 있는 카드는 커서를 가리지 않게 약간 떨어져 표시하고, 시작 카드에서 커서까지 선을 연결한다. 현재 대상, 비용 및 사용 가능 여부를 표시한다. 대상이 유효하지 않으면 선과 안내 문구로 구분한다.
- 단일 적 대상은 적 하나에 놓는다. 전체 대상 기술은 모든 유효 적을 강조하고 명확한 전체 대상 영역에 놓는다. 자신·아군 대상과 대상 없는 기술은 규칙에 맞는 영역에 놓는다. 이 구분은 기술별 검증된 대상 규칙이 있어야 활성화한다.
- 조준 중 카메라를 잠시 고정한다. 드래그 종료·취소 시 카메라를 복원한다. 카메라 이동, 포커스 이탈, 창 크기 변경, 전투 상태 갱신 시에는 안전하게 취소하거나 유효성을 재확인한다.
- 요청에는 전투·상태 버전·카드 인스턴스·대상·고유 요청 ID를 담는다. 클라이언트는 전송 후 처리 중임을 표시하고, 서버 확정 전 HP나 에너지를 확정하지 않는다. 응답 실패·시간 초과에는 재동기화와 재시도 안내를 제공하며 같은 요청의 중복 처리를 방지한다. 자동 재시도 여부는 서버 중복 방지 구현을 검증한 뒤 결정한다.
- 드래그가 어려운 사람을 위해 카드 클릭 후 대상 클릭, 키보드 선택 및 취소를 제공한다. 색만으로 유효 여부를 구분하지 않는다.

## 이야기와 이벤트의 화면 원칙

분기 지도에서 이벤트 노드가 확정되면 전투 HUD 대신 **장면·상황 설명·선택지**를 중심으로 보여준다. 전장 카메라를 강제로 유지할 필요는 없다. 이야기는 참여자가 왜 선택해야 하는지 알려주고, 선택지는 비용과 알려진 결과를 명확하게 보여준다.

```text
┌ 이벤트 이름 ─────────────────────────── 진행 상황 / 닫기* ┐
│                                                           │
│   ┌─────────────────────┐  낯선 장소에 도착했다.          │
│   │                     │  주변을 살펴보니 …              │
│   │   장면 이미지 또는  │                                 │
│   │   월드 연출 영역    │  [선택지 A] 알려진 비용·효과    │
│   │                     │  [선택지 B] 알려진 비용·효과    │
│   │                     │  [떠나기] 조건이 허용할 때      │
│   └─────────────────────┘                                 │
│             참가자 상태 · 선택 대기 / 서버 처리 중        │
└───────────────────────────────────────────────────────────┘
* 닫기는 화면을 닫는 것과 선택·이탈을 구분하며, 재진입할 수 있어야 한다.
```

장면은 이벤트의 분위기를 전달하는 삽화 또는 재사용 가능한 월드 장면을 사용한다. 텍스트는 제목, 짧은 도입, 선택 결과로 나누고 필요할 때 스크롤한다. 긴 문장이나 번역에도 선택 버튼이 가려지지 않게 한다. 이미지를 제공할 수 없다면 해당 이벤트의 제목과 설명, 테마 배경으로 상황을 전달하고 이미지 누락으로 진행이 막히지 않게 한다. 중요한 선택 정보는 이미지에만 넣지 않는다.

다음은 화면 구성만 보여주는 **가상의 예시**이며 실제 이벤트나 보상 규칙이 아니다.

```text
제목: 숲속의 작은 쉼터
장면: 낡은 표지판과 비어 있는 야영지
설명: 숲길 옆에서 오래된 쉼터를 발견했다. 주변은 조용하다.
선택: [살펴보기]  [그냥 지나가기]
결과: 서버가 확정한 실제 결과와 변화한 자원을 표시
```

실제 콘텐츠는 기존 기획에서 확인된 사실에 근거해 작성하고, 내용이 정해지지 않은 노드는 미완성으로 관리한다. 사건·비용·보상을 예시 값으로 실제 게임에 넣지 않는다.

## 노드별 연출과 스토리 진행

| 장면 | 보여줄 내용 | 다음 흐름 |
|---|---|---|
| 막 시작 | 막의 장소·분위기와 목표를 짧은 제목, 설명, 배경으로 전달 | 분기 지도 |
| 일반·엘리트 조우 | 적의 정체와 상황을 짧은 조우 문구·장면으로 표시 | 전장 진입 |
| 물음표 이벤트 | 사건 장면, 설명, 조건과 선택지 | 확정 결과 → 지도 |
| 상점·휴식 | 장소를 알아볼 수 있는 배경과 간단한 상황 설명, 기존 기능 UI | 처리 완료 → 지도 |
| 보스 조우·막 종료 | 보스와 관련된 상황, 승리 후 막의 변화 | 전투 또는 다음 막 지도 |
| 모험 종료 | 도달한 막, 주요 결과와 마무리 문구 | 모험 메뉴 |

지도는 독립 분기 UI를 유지한다. 노드 진입마다 긴 텍스트를 강제하지 않도록 짧은 장면을 기본으로 하고, 다시 보기와 넘기기 기능을 제공한다. 넘기기가 다른 참가자의 진행에 미치는 영향은 협동 규칙 확정 전 결정하지 않는다.

## 협동 및 데이터 설계

모든 참가자는 동일한 사건, 현재 단계와 서버가 확정한 결과를 볼 수 있어야 한다. 선택이 공동인지 개인별인지, 투표·동률·이탈을 어떻게 처리하는지는 이벤트별 규칙이 아직 필요하다. 규칙이 없는 선택을 임의로 실행하지 않는다. 처리 중에는 대기 상태와 참여자 현황을 표시하고, 재접속 시 현재 단계와 확정된 결과를 복원한다. 선택 결과는 중복 적용되지 않도록 서버가 관리한다.

이야기 데이터는 이벤트 ID, 번역 키, 장면 이미지 참조, 단계별 본문, 선택지, 가시 조건, 규칙 효과 참조 및 결과 문구를 분리해 관리한다. 서버는 선택 가능 조건과 효과를 검증하고, 클라이언트는 허용된 상태를 표현한다. 이미지 누락, 번역 누락, 잘못된 효과 참조 및 긴 문자열을 검증한다. 실제 선택 결과를 미확정 문구나 그림으로 대신하지 않는다.

## 구현 및 검수 순서

1. 현 시험 전투에 카드 드래그와 기존 클릭 대안을 연결하고 취소·중복·지연을 검증한다.
2. 이야기 화면의 공통 틀을 만들고 가상 예시 데이터로 화면 크기·빈 이미지·긴 번역을 검증한다. 예시를 실제 플레이 콘텐츠로 공개하지 않는다.
3. 기획된 실제 이벤트의 텍스트·이미지·선택 효과를 준비하고 서버 규칙에 연결한다.
4. 지도, 보스 및 막 전환에 짧은 상황 설명을 더하고 협동 선택 정책과 재접속을 검증한다.
5. 전용 카메라가 준비되면 각도·가림·여러 대상 크기에서 드래그 판정을 검증한다.
