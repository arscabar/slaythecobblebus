# CobbleSpire 0.6.0-dev 릴리즈 후보 초안

2026-11-14 / COBB-6. 독립 검토·테스트·최종 패키징 전의 개발 후보이며 완성된 운영 릴리즈가 아니다.

## 이번 후보

기존 원격 main의 1~4인 협동 시험 전투, 공동 턴·적 HP 배율, 예상 피해 핑·동료 피해량, 고딕 HUD, 전용 월드 전장, 덱 이동 연출, 승리 카드 보상, 21개 음악/징글과 아트 자료를 포함한다.

보관된 미반영 작업을 복구해 화면을 닫아도 표시되는 전투 HUD, F10으로 여는 커서 조작, 숫자키 카드 사용, 전장 중심 회전/높이/줌과 관전 위치 시점, 실제 능력치·상태·회복 피드백, 취소 가능한 전원 항복 투표를 통합했다. 항복으로 진행점수나 전리품을 만들지 않으며 진행 중 모험 종료 버튼으로 투표를 우회할 수 없다. 연결 종료 시에는 기존 협동 탈퇴 절차를 유지한다.

Windows 빌드 스크립트의 머신 고정 경로를 제거하고 JDK/Gradle 캐시를 인자로 받도록 했다. 원본과 stash는 별도로 보존했다. 자세한 커밋/누락 조사와 파일별 검토 가이드는 `COBB-6-audit.md`에 있다.

## 빌드·의존성

- Minecraft 1.21.1 / Java 21 / Fabric Loader 0.17.2 이상.
- 빌드 고정값: Gradle Wrapper 8.14.3, Fabric Loom 1.11.8, Kotlin 2.2.20, Fabric API 0.116.6+1.21.1, Fabric Language Kotlin 1.13.6+kotlin.2.2.20, Cobblemon 1.7.3(Modrinth 버전 ID `kF7CvxTo`).
- 대상 환경: COBBLEVERSE 1.7.42. CobbleLeague·CobbleSynergy 의존성은 없다. 서버와 클라이언트 모두 **동일한 후보 JAR / 프로토콜 7**을 사용해야 한다.

```powershell
# JAVA_HOME은 JDK 21 경로로 설정한다.
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_slay.ps1
# 또는 설치된 JDK/캐시를 명시한다.
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_slay.ps1 -JavaHome '<JDK21>' -GradleUserHome '<GradleCache>'
# 폐기용 QA 모드 컴파일 (배포에 포함하지 않는다)
.\gradlew.bat -p integration-tests build --no-daemon --console=plain
```

Linux/macOS에서는 JDK 21 환경에서 `./gradlew test build`를 실행한다. 의존성 다운로드에는 인터넷과 쓰기 가능한 Gradle 캐시가 필요하다.

배포 후보는 `build/libs/cobblespire-0.6.0-dev.jar`이며 `-sources.jar`는 모드 설치 파일이 아니다. 전체 소스 스냅샷은 정확한 후보 커밋의 `git archive`로 생성하며 `.git`, 로컬 런타임, 빌드 캐시, 게임 데이터는 포함하지 않는다. 첨부 패키지의 `BUILD-REPORT.md`, `MANIFEST.json`, `SHA256SUMS`에서 실제 커밋·검증 결과·바이너리 해시를 확인한다.

## 검증 수준과 제한

공식 빌드·JUnit 테스트·QA 모드 컴파일·JAR의 버전/리소스/mixin 참조 검사를 후보 제작 단계에서 수행한다. 구체적인 실행 결과는 첨부 빌드 보고서가 기준이다. 과거 버전의 로딩 기록은 이번 후보의 실제 실행 검증을 대신하지 않는다.

3막 지도·공동 경로 선택·상점·휴식·유물·진화 이벤트 노드는 완성되지 않았다. 전투 조우 순환과 관련 아트/음악 번들이 전체 로그라이크 진행 구현을 뜻하지 않는다. 미지원 원본 기술/폼/특성은 기존 호환성 차단을 유지한다. 실제 2~4인 연결, 클라이언트 mixin 적용과 입력·시점 복원, 게임 플레이 회귀는 독립 검토/테스트 단계의 확인 대상이다.

이 단계에서 운영 서버/클라이언트 파일 교체·재시작이나 GitHub 공개 릴리즈 게시는 수행하지 않는다. 원격 브랜치 반영 및 GitHub 인증 상태는 첨부 빌드 보고서에 성공/미완료를 구분해 기록한다.
