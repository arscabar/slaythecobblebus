# 전장·플레이어 위치와 층 이동 설계안

이 문서는 공간 연출 설계안이다. 0.4.0-dev에서 1인 월드 경기장·출전/적 엔티티·측면 관전 구역·분리 공중 카메라를 시제품으로 연결했다. 협동과 본문의 나머지 연출이 모두 구현된 것은 아니다. 실제 범위는 `WORLD_ARENA.md`를 참고한다. 기본 규칙은 `GDD-v4.1.md`, 수정 우선순위는 `GDD-v4.2.md`를 따른다. 특히 지도는 월드에서 걸어 다니는 지도가 아니라 독립 분기형 UI이며, 플레이어당 파티 3마리 중 출전은 1마리다. 적은 1~3마리다. 지도 UI는 노드 선택 때만 열고, 노드의 내용은 공간 연출로 보여준다.

## 기본 경험

카메라는 전장의 경계에서 안쪽을 바라본다. 화면 중앙에는 포켓몬의 전신과 행동 공간을 남기고, 플레이어의 시점과 모델은 조작에 방해되지 않게 한다. 전투 중에는 참가자 전원이 같은 전장 상태를 보되, 각자의 화면에는 자신의 출전 포켓몬이 잘 보이는 개인 카메라를 쓴다. 다른 플레이어의 시점이 바뀌어도 전투 위치나 판정은 바뀌지 않는다.

```text
화면 구성 (카메라에서 본 모습)
┌──────────────────────────────────────────┐
│               적 A    적 B    적 C       │
│              적 포켓몬과 인텐트           │
│                                          │
│          기술 이동과 피격 연출 공간       │
│                                          │
│     아군 2       내 포켓몬      아군 3    │
│   HP와 상태는 각 포켓몬 가까이에 표시     │
│──────────────────────────────────────────│
│     작은 손패 · 에너지         턴 종료    │
└──────────────────────────────────────────┘
```

카드와 정보는 화면 아래 가장자리에만 기본 표시한다. 상세와 전투 기록은 요청 시 펼친다. 포켓몬에 붙은 HP/인텐트는 화면상 겹침을 피하도록 배치하며, 가려지거나 화면 밖일 때 가장자리 표시로 대체한다. 카드 선택·대상 선택 시에만 필요한 조작을 강조하고, 적 행동 중에는 손패를 접어 전장에 집중한다.

## 전장 평면과 플레이어

```text
위에서 본 전장 (예시, 실제 크기는 모델 크기 검증 후 결정)
                         적 진영
                  E1       E2       E3

                    행동 / 이펙트 공간

               A1     A2     A3     A4
                         아군 진영
               P1     P2     P3     P4
                  카메라가 바라보는 방향 ↑
```

A는 출전 포켓몬 자리, P는 해당 플레이어의 대기 위치다. P는 원칙적으로 전투 행동 경로 밖의 안전한 자리이며, 플레이어 모델이 포켓몬이나 다른 플레이어의 시야를 가리지 않게 한다. 전투 중 자유 이동을 제한하는 안을 우선 검토한다. 단, 카메라 회전과 UI 조작은 가능해야 한다. 제한 범위 및 기존 월드 행동 차단은 실제 구현 전에 검증한다. 카메라는 자신의 플레이어 뒤에서 고정된 각도로 전장을 조망하고, 캐릭터·지형에 가려지면 위치를 조정한다. 필요하면 플레이어 모델을 해당 클라이언트에서 숨기는 대안을 제공한다.

이 배치는 논리적 슬롯의 제안이며 전장의 좌표가 기술 사거리나 피해 판정에 영향을 주지 않는다. 각 클라이언트가 자기 캐릭터를 잘 보기 위해 카메라만 조정한다. 서버는 참가자와 포켓몬의 슬롯을 공유하므로 상대 위치는 일관된다.

## 인원별 포켓몬 배치

| 참가자 | 아군 출전 배치 | 적 배치 |
|---|---|---|
| 1명 | 중앙 A2 또는 중앙에 가까운 단일 슬롯 | 1마리는 중앙, 2마리는 좌우, 3마리는 좌·중·우 |
| 2명 | 중앙 양옆 A2·A3 | 위와 동일 |
| 3명 | 좌·중·우로 균등 배치 | 위와 동일 |
| 4명 | A1~A4 균등 배치 | 위와 동일 |

실제 슬롯 좌표는 인원수에 따라 중심 정렬한다. 슬롯은 전투 시작 시 참가자 ID 기준으로 확정하고 전투 중 재정렬하지 않는다. 연결이 끊겨도 자리를 유지해 재접속 시 같은 위치로 복귀한다. 중간 참가 허용 여부는 미결이다. 모델의 크기와 충돌 범위에 따라 간격을 조정하고, 대형 모델이 가리지 않도록 카메라 거리와 높이를 함께 보정한다.

파티의 **나머지 두 마리는 출전하지 않는다.** 따라서 1인 전투에 3마리를 모두 배치하거나 4인 전투에 12마리를 동시에 출전시키지 않는다. 대기 포켓몬은 화면의 파티 목록에서 확인한다. 교체가 확정되면 같은 아군 슬롯에서 기존 포켓몬이 퇴장하고 새 포켓몬이 등장한다. HP·상태와 손패 교체는 서버의 확정 상태를 기준으로 보여준다. 대기 포켓몬의 장식용 등장도 출전 상태로 오해될 수 있으므로 기본안에서는 제외한다.

## 전투 진입부터 종료까지

1. 지도에서 도달 가능한 전투 노드를 선택한다. 협동에서는 서버가 선택 결과를 확정한다.
2. 화면을 짧게 전환하고 전용 전장에 참가자를 배치한다. 기존 플레이어 위치와 복귀 정보를 서버가 보관한다. 전장 생성 방식과 차원 사용은 아직 결정되지 않았다.
3. 참가자와 출전 포켓몬, 적을 슬롯에 배치하고 카메라를 조정한다. 준비가 끝나기 전에는 행동을 받지 않는다.
4. 포켓몬 등장 후 적 인텐트와 플레이어 페이즈를 표시한다. 행동 시 공격자→대상→결과 순서로 연출하며, 전체 대상 공격은 각 대상의 결과를 각각 보여준다.
5. 승패가 서버에서 확정되면 마지막 행동과 결과를 보여준다. 승리 시 보상 선택으로, 패배 시 모험 결과로 이동한다.
6. 노드가 끝나면 지도에 현재 위치와 다음 경로를 보여준다. 런을 종료하거나 이탈하면 안전한 기존 위치로 복귀한다.

지연·연결 끊김·재접속 시에는 서버 상태를 다시 받아 현재 전장, 슬롯, 페이즈와 결과를 복원한다. 오래된 연출을 반복하지 않는다. 플레이어 위치 저장·복귀와 임시 전장 정리는 서버 종료나 실패 상황을 포함해 별도 구현 및 검증이 필요하다.

## 다음 층과 막 이동

여기서 층은 분기 지도상의 다음 노드 깊이를 뜻한다. **물리적으로 계단을 걷거나 별도 월드 좌표로 이동해야 한다는 뜻은 아니다.** 전투·이벤트·상점 등 현재 노드의 처리가 끝나면 지도가 열리고 현재 노드에서 이어진 다음 층의 선택지만 활성화된다. 협동 투표와 서버 확정 후 선택한 노드의 장면으로 전환한다. 이동 중에는 선택 결과와 목적지를 짧게 보여준다.

막의 보스를 완료한 뒤에는 보상과 막 전환 연출을 거쳐 다음 막 지도를 연다. 최종 막 완료 후에는 결과 화면으로 간다. 이동 연출과 실제 전장 재사용 여부는 구현 선택 사항이며, 다음 층 진입 규칙과 투표 동률 처리는 확정된 서버 규칙에 맞춰야 한다.

## 카메라와 조작의 안전장치

- 플레이어 수, 화면비, GUI 배율, 크기가 큰 포켓몬과 지형 가림에 따라 카메라 거리·각도를 조정한다. 전신과 주요 행동 공간이 보이는지 확인한다.
- 고정 카메라가 불편할 수 있으므로 제한된 각도 조절, 연출 축소와 흔들림 끄기를 제공한다. 카메라 설정은 개인별로 저장한다.
- 포켓몬을 직접 클릭해 대상 선택하되 겹침이나 화면 밖 대상은 이름 목록과 키보드 선택으로 보완한다. 선택 대상과 행동 불가 이유를 명확히 표시한다.
- 월드가 보이는 전장이라면 블록·다른 엔티티·날씨가 시야와 조작을 방해하지 않는지 확인한다. 외형 연출과 실제 서버 판정을 분리한다.

## 구현과 검증 순서

1. 현재 독립 전투를 유지하면서 임시 전장과 1인 카메라·출전 슬롯을 시제품으로 구현한다. 실제 게임 화면에서 모델 가림과 조작성을 확인한다.
2. 서버 확정 행동을 등장·공격·피해·교체 연출로 연결하고, 현재의 불투명 전체 패널을 가장자리 조작 영역으로 대체한다.
3. 2~4인 슬롯 및 개별 카메라, 동시 입력·이탈·재접속·복귀를 검증한다. 협동 규칙은 별도 구현이 필요하다.
4. 지도 노드 선택, 보상 및 다음 층 전환을 서버 상태와 연결한다. 막 전환과 실패 복구까지 확인한다.

검수는 1~4인 각각, 적 1~3마리, 작은 화면과 여러 GUI 배율, 큰 포켓몬, 교체·기절·동시 행동·재접속을 포함한다. 사용자 관점에서는 전신이 보이는지, 행동 대상과 결과를 이해할 수 있는지, 카드 조작 중에도 전장이 읽히는지를 실제 화면에서 확인한다.

## 협동: 참가자별 전황 표시와 동기화

### 공통 전장과 개인 화면

서버가 하나의 전투 상태와 행동 순서를 확정한다. 모든 참가자는 같은 포켓몬 슬롯, HP·상태, 적 인텐트, 페이즈와 행동 결과를 받는다. 각 클라이언트는 같은 장면을 자신의 위치에서 볼 수 있게 카메라만 조정한다. 상대 배치를 클라이언트마다 재정렬하지 않는다. 카메라로 잘 보이지 않는 아군이나 적은 화면 가장자리의 대상 표시와 목록에서 확인한다. 가림이 심할 경우 같은 공유 전장을 조망하는 공통 카메라로 전환할 수 있다.

자신에게 중요한 정보는 강조한다. 내 출전 포켓몬에는 `나` 표식, 아군에게는 참가자 이름과 출전 포켓몬 이름을 붙인다. 내 에너지·손패·대기 파티와 선택 대상은 내 조작 영역에 둔다. 다른 참가자의 에너지·준비 상태 공개 여부와 손패 공개 범위는 협동 규칙 확정 전 미결이며, 정보를 임의로 공개하지 않는다. 공개된 아군 HP와 상태는 전장 위 표식과 접을 수 있는 팀 목록에서 확인한다. 색상 외에 이름과 문구로도 소유자를 구분한다.

```text
공유 전장: 실제 슬롯은 모든 화면에서 동일
                 적 A             적 B
              예고: 전체 공격 8~12

            P1의 포켓몬     P2의 포켓몬
                HP 80             HP 55

P1 화면: [나 · P1] 강조 / 내 손패·에너지 / P2 상태
P2 화면: [나 · P2] 강조 / 내 손패·에너지 / P1 상태
```

적의 전체 대상 공격 예고는 각 대상의 능력치에 따라 예상 결과가 다를 수 있다. 각자 화면의 기본 표시는 **자신의 출전 포켓몬에 대한 예상치**임을 명시하고, 팀 목록이나 상세에서 공개 가능한 아군별 예상치를 확인한다. 표시된 수치가 범위나 조건부 예측이라면 그 사실을 명시한다. 실제 피해는 서버 결과를 사용한다.

### 행동 표시 순서

1. 서버가 행동을 접수하고 순서를 확정한다. 클라이언트는 처리 대기 상태를 표시하되 결과를 미리 확정하지 않는다.
2. 행동자와 기술, 대상 또는 전체 대상 표시를 모든 참가자에게 보여준다. 자신의 행동인지 아군 행동인지 이름으로 구별한다.
3. 행동자에서 대상까지 연출하고, 각 대상 위치에 개별 피해·회복·상태 변화를 표시한다. 화면 밖 대상의 결과도 전투 기록에 남긴다.
4. 서버가 확정한 HP와 상태를 반영하고 다음 행동으로 넘어간다. 참가자별 연출 속도나 카메라는 판정에 영향을 주지 않는다.
5. 짧은 최근 기록에 행동자·대상·결과를 남기고, 펼치면 놓친 결과를 확인한다. 정보가 빠르게 연속 발생하면 순서를 유지해 읽을 시간을 확보한다.

협동 플레이어의 동시 요청은 서버가 정한 순서로 처리하며 실패한 요청에는 이유를 요청자에게 알려준다. 턴 준비와 공동 적 페이즈 진입 방식은 별도 규칙 확정 후 표시한다. 행동 순서가 개인 화면마다 달라 보이지 않도록 서버가 부여한 순서와 식별자를 사용한다.

### 지연·재접속과 검증

상태 스냅샷에는 전투 식별자와 개정 번호를 포함하고, 행동 기록에는 순서와 고유 식별자를 포함한다. 클라이언트는 중복 또는 오래된 상태를 무시한다. 누락이나 순서 불일치가 감지되면 최신 상태를 다시 요청하고 연출을 맞춘다. 재접속자는 현재 슬롯·HP·페이즈·인텐트부터 복원하고 지나간 연출을 전부 재생하지 않는다. 이 구조는 설계 목표이며 현재 협동 구현이 완성됐다는 뜻은 아니다.

검수에서는 2~4명의 화면을 동시에 기록해 같은 행동 순서와 최종 상태가 보이는지 비교한다. 각자의 전체 공격 예상치가 해당 대상 기준인지, 화면 밖 대상 결과를 확인할 수 있는지, 카메라 가림과 해상도 차이에도 소유자를 구분할 수 있는지 확인한다. 지연·중복 패킷·동시 입력·끊김 및 재접속 후에도 동일한 결과로 수렴하는지 시험한다.

## 플레이어 자리와 이동: 권장안

앞의 전투 중 자유 이동 제한은 시제품에서 검증할 가설이며, 전투 내내 의자에 강제 착석시키거나 완전히 움직이지 못하게 한다는 확정 규칙이 아니다. 권장안은 **전장 뒤편의 개인 관전 구역에서 제한적으로 자유 이동**하는 것이다. 카메라는 우선 본인의 실제 위치에서 바라보며, 필요할 때 전장 전체를 조망하는 별도 시점으로 전환한다. 별도 시점에서도 입력은 자신의 손패와 출전 포켓몬에만 적용된다.

```text
                    적 1     적 2     적 3

                    기술 연출 공간

               아군 1  아군 2  아군 3  아군 4
          ───────── 전투 영역 경계 ─────────
          │ P1 구역 │ P2 구역 │ P3 구역 │ P4 구역 │
          │ 이동과  │ 이동과  │ 이동과  │ 이동과  │
          │ 선택적 착석 / 관전 시점 전환 가능     │
          └──────── 뒤편 안전 경계 ─────────────┘
```

플레이어는 자신의 출전 포켓몬 뒤쪽에 배정된다. 전장 전체가 보이도록 아군보다 약간 높은 완만한 관전 구역을 기본으로 검토한다. 플레이어 수가 적으면 사용 중인 자리와 아군 슬롯을 중앙으로 모은다. 네 명일 때도 머리 위로 이름이 겹치거나 앞사람 모델이 다른 사람의 포켓몬을 가리지 않는 간격이 필요하다. 그림은 개념도이며 블록 단위 거리와 높이는 포켓몬 크기·시야각·화면비에 따른 게임 내 시제품 측정 후 정한다.

### 이동과 의자 선택지

| 방식 | 장점 | 문제 | 판단 |
|---|---|---|---|
| 완전 고정 또는 강제 착석 | 카메라와 배치를 예측하기 쉽다 | 움직일 수 없고 다른 참가자를 보는 재미가 줄어든다. 멀미나 답답함이 생길 수 있다 | 초기 로딩·짧은 전환 때만 고려 |
| 개인 관전 구역에서 제한 이동 | 월드 안에 있는 느낌과 안정적인 시야를 함께 확보한다 | 경계 표시, 시야 가림, 다른 플레이어와의 충돌 처리가 필요하다 | 기본 권장안 |
| 전장 전체 자유 이동 | 자연스럽게 돌아다닐 수 있다 | 기술 연출 가림, 포켓몬과 겹침, 개인별 시야 차이, 전장 이탈을 처리해야 한다 | 기본안으로 채택하지 않음 |

의자는 **선택적 장치**로 제안한다. 플레이어가 자신의 자리에 앉으면 안정된 관전 시점과 앉은 자세를 제공하고, 언제든 일어나 개인 구역 안을 이동할 수 있다. 앉지 않아도 모든 전투 기능을 이용할 수 있어야 한다. 의자가 포켓몬을 가리거나 모델이 겹치면 장식 형태나 서 있는 관전 자리로 대체한다. 의자나 착석 자체는 시제품 검증 전의 제안이다.

전투 영역으로 들어가거나 다른 사람의 시야를 지속적으로 가리는 일은 막아야 한다. 개인 구역 경계에 접근하면 부드러운 시각 표시를 보여주고 이동을 제한한다. 플레이어끼리 충돌하면 좁은 공간에서 서로 막힐 수 있으므로 참가자 간 충돌 완화도 검토한다. 이는 실제 서버 환경과 다른 모드와의 상호작용을 검증한 뒤 결정한다. 전투와 무관한 파괴·상호작용 차단 범위도 별도 정의한다.

### 입력과 카메라

- **이동 모드:** 월드에서 걷고 주변을 바라본다. 카드 조작 패널은 접혀 있고 지정 키로 연다. 마우스는 시점 조작에 사용한다.
- **전술 모드:** 지정 키를 누르면 카드와 대상 선택을 열고 마우스 커서를 사용한다. 이동 입력은 잠시 막되 언제든 모드를 닫아 복귀한다. 전투 결과에 영향을 주지 않는 개인 화면 전환이다.
- **관전 시점:** 필요할 때 전장을 위쪽에서 넓게 보는 개인 카메라로 전환한다. 실제 플레이어 몸은 안전 구역에 남는다. 다시 전환하면 원래 시점으로 돌아간다. 멀미를 줄이도록 카메라 이동을 짧게 하거나 즉시 전환하는 설정을 제공한다.
- **선택적 착석:** 의자 상호작용으로 앉고 일어난다. 착석 중에도 전술 모드와 관전 시점을 사용할 수 있다.

카드 조작 중에도 적 행동과 전황은 보인다. 대상 직접 클릭이 가림 때문에 어려우면 대상 목록과 키보드를 함께 제공한다. 채팅·메뉴·접근성 단축키와 입력이 충돌하지 않는지 확인해야 한다.

### 상황별 위치 처리

전투 진입 시 서버가 참가자별 안전 자리를 정하고 기존 복귀 위치를 보관한다. 이동 가능 상태가 준비되기 전의 전환 구간에는 짧게 입력을 제한할 수 있다. 교체할 때는 플레이어를 이동시키지 않고 해당 아군 슬롯에서 포켓몬만 교체한다. 기절·관전 중에도 플레이어는 안전 구역에 남고 전황을 볼 수 있다. 이탈자는 자리를 유지하고 재접속 시 안전한 개인 구역에 복귀시킨다. 전투가 끝나면 보상과 지도 흐름을 거쳐 런 종료 또는 이탈 시 보관된 안전 위치로 돌려보낸다. 서버 장애와 원래 위치가 안전하지 않은 경우의 대체 위치 및 정리 방식은 구현 시 명시하고 검증한다.

### 시제품에서 답해야 할 질문

1. 1~4인과 적 1~3마리, 가장 큰 포켓몬 조합에서 각 자리의 기본 시점으로 모든 대상을 볼 수 있는가?
2. 다른 플레이어가 서 있거나 이동·착석할 때 대상과 HP가 가려지는가? 가려진다면 자리 간격, 개인별 모델 가림 처리 또는 관전 시점으로 해결되는가?
3. 걷기와 카드 조작 전환이 자연스럽고, 커서가 풀리거나 카메라가 갑자기 움직이지 않는가?
4. 제한 경계가 눈에 띄고 불편하지 않은가? 실제로 의자에 자발적으로 앉고 싶은가?
5. 지연·이탈·재접속 및 전투 종료 후에도 안전한 위치와 정상 조작이 복원되는가?

## 시야 가림을 반영한 배치 수정

앞서 제안한 **자기 포켓몬 바로 뒤에서 실제 시점으로 관전하는 배치**는 대형 포켓몬이 적과 기술을 가릴 수 있으므로 기본안에서 철회한다. 플레이어의 월드 위치와 전투 카메라를 분리한다.

```text
위에서 본 전장
             적 1       적 2       적 3

             기술과 피해 연출 공간

          아군 1    아군 2    아군 3    아군 4

  관전 구역 P1~P4                         전장 가장자리
          ↘ 공중의 전술 카메라가 전장을 비스듬히 내려다봄
```

플레이어는 전장 측면의 안전한 관전 구역에 함께 배치하고, 전투 중 기본 화면은 전장 중앙을 비스듬히 내려다보는 개인별 가상 카메라로 제공한다. 플레이어 몸은 실제로 공중에 이동하지 않는다. 각 카메라는 같은 슬롯과 결과를 보며, 자신의 포켓몬이 잘 보이도록 시야를 조금 조정할 수 있다. 직접 월드를 둘러보거나 걸을 때는 관전 구역의 실제 시점으로 돌아가며, 전투 시점으로 다시 전환할 수 있다. 가상 카메라 사용 중 이동 입력이 실제 몸을 예상치 않게 이동시키지 않도록 한다.

카메라 높이·거리·각도는 아군과 적 전체의 화면상 범위를 기준으로 조정한다. 다만 자동 조정만으로 모든 대형 모델의 가림이 해결된다고 가정하지 않는다. 가림 시에는 카메라 각도 변경, 일시적인 가림 개체 반투명 처리, 화면 가장자리 대상 표시 및 대상 목록을 순서대로 검토한다. 기술 이펙트는 가능하면 화면상 확인 가능한 경로와 높이로 연출하고, 가려져도 기술명·대상·피해 결과를 별도로 확인할 수 있게 한다. 반투명 처리와 이펙트 경로 변경은 실제 게임에서 외형 및 호환성을 시험해야 한다.

의자는 전장 측면 관전 구역에 두는 선택 사항이다. 착석이 카메라 전환의 필수 조건은 아니다. 전투 기본 시점, 측면 실제 시점, 의자 배치 및 자유 이동 범위는 1~4인과 대형 포켓몬 조합의 시야 시험을 거쳐 결정한다. 이 절이 앞 절의 카메라·플레이어 위치 제안보다 우선한다.
